## Per-point findings

### 1. Offset 整合（16..32 予約、survivors 不動）— ✅ 確認・予約域は read で無視

- serialize は 16..32 を書かず**zeroed のまま**、deserialize は 16..32 を**無視**。survivors の
  オフセット不動（schema 32..40 / counts 40..48 / property dir 48..56 / node-edge dir 56..64）。
- probe（`probe_reserved_range_ignored_and_roundtrip`）：
  - serialize 後 16..32 は全 0 ✓。
  - **16..32 に 0xAB を注入しても deserialize 後の header は原本と一致**（`h == h2`）。予約域の
    stray bytes が実フィールドに漏れない＝robust reader として正しい。
  - schema_root@32 / node_dir_root@56 / edge_dir_root@60 が期待値で read/write ✓（survivors 不動）。
- → reviewer テストとして恒久化（下記 E-1）。予約域が現状 read で無視される点は、将来 16..32 を
  再利用する際の前提として固定する価値が高い。

### 2. `CapacityExceeded` が真に dead — ✅ 完全削除・FFI 影響なし

  match も無し）。Phase 2b で construction sites が消えていたことの帰結で、変種削除は正当。
