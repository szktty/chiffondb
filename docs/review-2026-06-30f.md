## Per-point findings

### 1. Count/len 整合（counts = header field かつ directory len）— ✅ lockstep

- `store_topology_dir`（`file.rs`）が `node_dir_root`/`node_page_count`（または edge 版）を
  **必ず同時に**書き戻し `write_header()`。`node_page_count`/`edge_page_count` を別フィールド化せず
  directory len として再利用＝二重管理なし（single source of truth）。
- counts を更新する経路は `store_topology_dir` のみ。`topology.rs` の旧 `file.header.node_page_count
  = ...; write_header()` 直書きは削除され、全て `alloc_topology_page`（内部で push→store）経由に
  集約。片方だけ更新する経路は無い。
- **start-at-0 / 最初の alloc が logical 0 をマップ**：probe で確認。fresh 時 node=0/edge=0、
  最初の node `page_id=0`（→物理1, node dir 物理2）、最初の edge `page_id=0`（→物理3, edge dir
  物理4）、counts は 1/1 に。**page 0 の事前存在を仮定する箇所なし**。`deserialize` の `.max(1)`
  除去も 0 が valid になった整合で正しい。

### 2. 単一カウンタ上の mixed append（E-3 / E-2 carried）— ✅ 混同なし

- node/edge/property の record ページ **と** 3 directory のページが全て `append_page` を共有。
- probe（200 ノード + エッジを interleave, node 4ページ/edge 4ページ）：全 200 ノードが
  `node_type_id=1` で正しく read back。node_dir_root=`0x2`、edge_dir_root=`0x4` と**別ルート**。
  各 logical ページは自分の kind の directory 経由でのみ解決されるため、record ページ・directory
  ページ・node/edge の別 kind が物理的に混在しても**取り違えない**。
- DoD `topology_and_properties_interleave_on_the_append_tail`（200 ノード+プロパティ）も happy
  path を網羅。ordering edge case は probe + 本テストで確認、問題なし。

### 3. Rollback 完全性 — ✅ 3 directory すべて revert

- `FileSnapshot` が header 全体を保持（既存規律。新規 56..64 フィールドも自動的に revert 対象）

- DoD `rollback_unwinds_node_edge_and_property_growth_together` が Database レベルで node+edge+
  property を1トランザクションで成長→rollback→3種とも復帰、reopen 後も post-rollback 状態、を
